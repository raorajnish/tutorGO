# 1️⃣ Platform Owner vs Institute Users

You (platform owner) should **not be mixed with institute users**.

Use **Django superuser for platform admin**.

Flow:

```
You (platform admin)
↓
Create Institute
↓
Create Institute Owner User
↓
Give login credentials
↓
Owner logs in and manages organization
```

So:

```
Platform level
    |
Institute
    |
Users
```

# 2️⃣ User System (Best Architecture)

Use **one User table** with roles.

Do NOT create separate tables for admin/faculty/reception.

Better design:

```
User
 ├─ Owner
 ├─ Admin
 ├─ Faculty
 ├─ Reception
 └─ Student
```

Model:

```python
class User(AbstractUser):

    institute = models.ForeignKey(
        Institute,
        on_delete=models.CASCADE,
        null=True,
        blank=True
    )

    ROLE_CHOICES = (
        ('owner','Owner'),
        ('admin','Admin'),
        ('faculty','Faculty'),
        ('reception','Reception'),
        ('student','Student')
    )

    role = models.CharField(max_length=20, choices=ROLE_CHOICES)

    phone = models.CharField(max_length=15, blank=True)

    is_active = models.BooleanField(default=True)
```

This lets the **institute owner create users inside the institute**.

Example:

```

    |
    ├─ ENQUIRY (active)
    ├─ ADMISSION (active)
    ├─ ATTENDANCE (active)
    ├─ FEES (inactive)
```

---

### How backend checks module

Before accessing module:

```python
def module_enabled(institute, module_code):
    return InstituteModule.objects.filter(
        institute=institute,
        module__code=module_code,
        is_active=True
    ).exists()
```

So if institute doesn't subscribe to **FEES**, that module is blocked.

# 8️⃣ Batch System (Important)

A student might change batches.

So **never store batch directly in Student**.

Use mapping table.

```
StudentBatch
```

Example:

```python
class Batch(models.Model):

    institute = models.ForeignKey(Institute, on_delete=models.CASCADE)

    name = models.CharField(max_length=100)

    course = models.ForeignKey(Course, on_delete=models.CASCADE)

    start_date = models.DateField()

    end_date = models.DateField(null=True, blank=True)
```

Mapping:

```python
class StudentBatch(models.Model):

    institute = models.ForeignKey(Institute, on_delete=models.CASCADE)

    student = models.ForeignKey(Student, on_delete=models.CASCADE)

    batch = models.ForeignKey(Batch, on_delete=models.CASCADE)

    joined_at = models.DateField()
```

Why?

Students can:

```
Batch A → Batch B
```

# 9️⃣ Faculty Salary System

Two salary types:

```
Fixed salary
Per lecture
```

Model:

```python
class Faculty(models.Model):

    institute = models.ForeignKey(Institute, on_delete=models.CASCADE)

    user = models.OneToOneField(User, on_delete=models.CASCADE)

        choices=[
            ('fixed','Fixed'),

```

# 🔟 Fee Installments System (Very Important)

Don't store total paid only.

Use **Installment table**.

Example:

```python
class FeeInstallment(models.Model):

    student = models.ForeignKey(Student,on_delete=models.CASCADE)

    due_date = models.DateField()

    amount = models.DecimalField(max_digits=10, decimal_places=2)

    is_paid = models.BooleanField(default=False)
```

Payment table:

```python
class FeePayment(models.Model):

    installment = models.ForeignKey(FeeInstallment,on_delete=models.CASCADE)

    amount = models.DecimalField(max_digits=10, decimal_places=2)

    payment_date = models.DateField()

    payment_mode = models.CharField(max_length=20)
```

If student pays full:

```
mark all installments paid
```
